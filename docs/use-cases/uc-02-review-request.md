# UC-02 — рассмотреть заявку

| Поле | Значение |
| --- | --- |
| Цель | Согласовать или отклонить заявку на основании актуальных правил |
| Основной актор | Руководитель |
| Вторичные акторы | Сотрудник, LeaveOps |
| Триггер | Руководитель открывает `submitted`-заявку |
| Предусловия | Актор руководит отделом автора и не является автором |
| Постусловия | `approved` + history + outbox `upsert` либо `rejected` с причиной |

## Основной поток: согласование

1. LeaveOps показывает пересечения, покрытие и прогноз баланса.
2. Руководитель выбирает «Согласовать».
3. LeaveOps открывает `BEGIN IMMEDIATE` и повторяет все проверки.
4. LeaveOps атомарно сохраняет `approved`, историю и outbox-событие.
5. Руководитель получает бизнес-результат независимо от доставки в Bitrix24.

## Альтернативный поток: отклонение

1. Руководитель указывает причину.
2. LeaveOps сохраняет `rejected` и запись истории; интеграционное событие не создаётся.

## Исключения

- Overlap, недостаточный баланс или покрытие: `conflict`, состояние не меняется.
- Пустая причина отказа: `reason_required`.
- Своя заявка или другой отдел: `forbidden`.
- Статус уже изменён: `invalid_transition`.

**Правила:** `RULE-02`, `RULE-04`–`RULE-10`.<br>
**Требования:** `BR-01`, `BR-02`, `FR-03`, `FR-04`, `FR-10`, `NFR-01`.
**Критерии:** `AC-APP-001`–`AC-APP-006`.
