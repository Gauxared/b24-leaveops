# UC-06 — синхронизировать календарь

| Поле | Значение |
| --- | --- |
| Цель | Доставить pending-команду в календарь без изменения бизнес-статуса заявки |
| Основной актор | Руководитель в UI / администратор интеграции в CLI |
| Поддерживающий внешний актор | Bitrix24 Calendar |
| Внутренний компонент | `IntegrationWorker` |
| Триггер | Ручной запуск обработки outbox |
| Предусловия | Есть pending/expired-processing событие; адаптер настроен |
| Постусловия | `delivered` с `external_id` либо `pending` с `last_error` |

## Основной поток

1. Руководитель запускает синхронизацию в демо-UI либо администратор выполняет `sync`/`b24-sync` в CLI.
2. Внутренний `IntegrationWorker` читает доступные outbox-события.
3. Worker атомарно выбирает старейшее событие, увеличивает `attempts`, задаёт `worker_token` и lease.
4. Для `update`/`cancel` worker находит ID последнего доставленного `upsert`/`update`.
5. Адаптер обращается к внешнему актору Bitrix24 Calendar и выполняет `upsert`, `update` или `cancel`.
6. Worker сохраняет `delivered`, `external_id` и `delivered_at`.

## Альтернативные потоки

- Перед `add` REST-адаптер ищет `[LeaveOps:<request_id>]` и возвращает найденный ID.
- Если cancel-цель отсутствует, операция считается идемпотентно выполненной.
- При ошибке событие возвращается в `pending`, сохраняет `last_error`; заявка не меняется.
- Просроченный lease позволяет следующему worker повторить обработку.

## Исключения

- Неизвестный сотрудник или отсутствующий `section_id`: диагностическая ошибка, событие остаётся `pending`.
- `update` без числового `external_id`: API не вызывается, ошибка остаётся в outbox.
- В UI синхронизацию может запустить только руководитель.

Автоматический scheduler или постоянно работающий background worker рассматривается только как возможное production-развитие и не входит в текущий Use Case.

**Требования:** `BR-03`, `BR-05`, `FR-11`–`FR-13`, `NFR-02`, `NFR-03`, `NFR-08`.
**Критерии:** `AC-INT-001`–`AC-INT-003`, `AC-MAP-001`, `AC-MAP-002`.
