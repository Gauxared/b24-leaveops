# UC-03 — перенести согласованный период

| Поле | Значение |
| --- | --- |
| Цель | Изменить даты согласованной заявки только после нового решения |
| Основной актор | Сотрудник, затем руководитель |
| Внутренние компоненты | LeaveOps Service, outbox |
| Связанный сценарий | Доставка изменения выполняется отдельно по `UC-06` |
| Триггер | Автор предлагает новый период для `approved`-заявки |
| Предусловия | Нет открытого `reschedule_proposal(submitted)` |
| Постусловия | При согласовании даты изменены; при отказе или конфликте старый период сохранён |

## Основной поток

1. Автор указывает отличающиеся новые даты и необязательный комментарий.
2. LeaveOps создаёт предложение `submitted`; заявка сохраняет `approved` и старые даты.
3. Руководитель видит старый и новый периоды и результат preview.
4. Руководитель согласует перенос.
5. LeaveOps повторяет overlap, balance и coverage внутри транзакции.
6. LeaveOps обновляет даты и историю.
7. Pending `upsert` получает новый payload; если создание доставлено, создаётся `update` с известным `external_id`. Внешняя доставка не входит в этот бизнес-сценарий и запускается отдельно по `UC-06`.

## Альтернативные потоки

- Руководитель отклоняет перенос с причиной: proposal становится `rejected`, заявка не меняется.
- При конфликте proposal остаётся `submitted`, чтобы его можно было отклонить; заявка не меняется.

## Исключения

- Те же даты: `unchanged_dates`.
- Уже есть открытое предложение: `reschedule_pending`.
- Чужой автор или не свой руководитель: `forbidden`.
- Пустая причина отклонения: `reason_required`.

**Правила:** `RULE-04`, `RULE-08`, `RULE-09`, `RULE-11`, `RULE-12`.<br>
**Требования:** `BR-04`, `FR-09`, `FR-10`, `NFR-01`.
**Критерии:** `AC-RES-001`, `AC-RES-002`.
