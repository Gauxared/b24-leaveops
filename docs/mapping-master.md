# Локальная проверка карты Bitrix24

Эта процедура связывает только синтетические `employee_id` LeaveOps с числовыми `owner_id` пользователей **тестового** портала Bitrix24. Она не импортирует пользователей, не вызывает REST API и не создаёт разделы календаря. Файл карты предназначен для локальной директории `runtime/`, которая исключена из Git.

## Подготовка

Скопируйте образец в игнорируемую директорию и укажите только известные ID пользователей тестового портала:

```powershell
Copy-Item data/bitrix24-mapping.example.json runtime/bitrix24-mapping.json
python -m leaveops --db runtime/leaveops.db b24-mapping-check --mapping runtime/bitrix24-mapping.json
```

Перед проверкой должна существовать заполненная синтетическая база: `python -m leaveops init`.

## Что проверяет команда

`b24-mapping-check` читает локальный JSON и список активных синтетических сотрудников из указанной базы. В результате она показывает:

- сотрудников, которые сопоставлены и ещё не сопоставлены;
- лишние ключи карты, которых нет в LeaveOps;
- некорректные `owner_id` и случаи, когда один пользователь Bitrix24 назначен двум сотрудникам;
- сотрудников без `section_id`;
- три флага готовности: к созданию разделов, к полному охвату синтетического отдела и к полной синхронизации.

Поле `writes_to_bitrix24` всегда равно `false`. Частичная корректная карта допускается для `b24-setup`: это нужно текущему тестовому контуру с тремя пользователями. Для полной синхронизации всех шести синтетических сотрудников она намеренно не считается готовой, пока не появятся остальные проверяемые учётные записи.

## Действие, которое пишет в портал

Только после локальной проверки можно задать переменные окружения и выполнить:

```powershell
$env:B24_MAPPING_FILE="runtime/bitrix24-mapping.json"
python -m leaveops --db runtime/leaveops.db b24-setup
```

`b24-setup` повторно выполняет предконтроль, затем обращается к Bitrix24 и создаёт либо находит личный раздел `LeaveOps — отсутствия` для каждого сотрудника из карты. Полученные `section_id` сохраняются атомарно в тот же runtime-файл. Эта команда меняет данные тестового портала; не запускайте её с рабочим webhook или картой рабочих пользователей.

## Проверенный объём

На 12 сентября 2026 года в тестовом портале подтверждены три владельца календаря. Поэтому в репозитории нет карты реальных людей и нет заявления о полной синхронизации шести сотрудников. Следующая внешняя проверка требует отдельно подготовить тестовые учётные записи и подтвердить, нужно ли добавлять владельца календаря в участники события.
