# Обзор продукта

## Задача

Даты отпусков, остатки, решение руководителя и календарь часто существуют отдельно. LeaveOps связывает их в один процесс: сотрудник подаёт заявку, руководитель сразу видит влияние на команду, а согласованное изменение попадает в Bitrix24 с отдельным техническим статусом.

## Участники процесса

| Роль | Результат |
| --- | --- |
| Сотрудник | Понятный статус заявки и возможность предложить новые даты |
| Руководитель | Решение с учётом пересечений, остатка и критичных ролей |
| HR | Сводная по доступным, использованным и запланированным дням |
| Администратор | Проверяемая карта пользователей и журнал доставки |

## Функции

| Область | Реализация |
| --- | --- |
| Заявки | Создание, отправка, согласование, отклонение и отмена |
| Доступность | Пересечения и минимальное покрытие аналитиков и разработчиков |
| Баланс | Начальный остаток, ежемесячное начисление, использованные и запланированные дни |
| Перенос | Новые даты вступают в силу только после повторного решения руководителя |
| Интеграция | Создание, обновление и удаление календарных событий через outbox |
| Надёжность | Повтор после ошибки, восстановление lease и защита от дублей |

## Разделение ответственности

Бизнес-статус заявки и статус внешней доставки хранятся отдельно. Руководитель может принять решение даже при временной недоступности Bitrix24; событие останется в очереди и будет доступно для повтора. Все бизнес-правила и проверки доступа выполняются на сервере.
