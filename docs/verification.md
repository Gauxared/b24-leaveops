# Результаты проверки

Дата последней локальной проверки: 13 сентября 2026 года. Среда: Windows, Python 3.12.10, Node.js 24, переносимый Java 21 и временные SQLite-базы. Данные синтетические.

## Автоматическая проверка в CI

Workflow [`.github/workflows/verify.yml`](../.github/workflows/verify.yml) запускается на `push` и `pull_request` с минимальным разрешением `contents: read`. Конфигурация фиксирует следующие проверки:

1. Python 3.12: `python -m unittest discover -s tests -v`.
2. Стандартный Python-валидатор: `python tools/verify_docs.py`.
3. Node.js 24: `node --check leaveops/static/app.js`.
4. Java 21 и PlantUML 1.2026.8: загрузка официального JAR, проверка SHA-256 и `--check-syntax` для 13 диаграмм.

Репозиторный валидатор завершается с ошибкой при битой относительной Markdown-ссылке, повторном или неизвестном каноническом ID, пропуске BR/RULE/FR/NFR/PP/RISK/UC в трассировке, Mermaid-блоке, некорректном BPMN/SVG XML, пересечении process границы sequence flow, message flow внутри одного process, отсутствии исходника/рендера, несоответствии документированной SQLite-схемы или HTTP-маршрутов. Отдельные регрессионные проверки фиксируют ручной старт worker, persisted outbox, внешнюю границу Mock Bitrix24 и отсутствие Integration Worker среди UML-акторов.

CI не рендерит SVG и не обращается к Bitrix24. Живые тесты требуют локального webhook и поэтому не включены в default workflow.

Команда `python -m unittest discover -s tests -v` завершилась результатом: **52 теста прошли**.

`node --check leaveops/static/app.js` завершился успешно. Все PlantUML-исходники локально прошли `--check-syntax`.

## Локальная проверка диаграмм

Обе BPMN 2.0 collaboration импортированы и отрисованы `bpmn-to-image`/`bpmn-js`. Структурно подтверждено, что sequence flow остаются внутри process, а message flow соединяют разные процессы.

В TO-BE:

- business commit записывает `approved`, history и persisted outbox;
- бизнес-процесс завершается без сообщения worker;
- отдельный процесс начинается ручным действием руководителя в UI или администратора в CLI;
- production scheduler отмечен как возможный, но не реализованный вариант;
- Bitrix24 остаётся внешним participant.

Тринадцать PlantUML-моделей прошли синтаксическую и визуальную проверку: две UML Use Case, две State Machine, логическая и физическая модели, C4 Context/Container, UML Component и четыре UML Sequence. Mock Bitrix24 расположен вне C4 boundary LeaveOps, а Integration Worker не показан UML-актором.

## Локальные демонстрационные сценарии

`python -m leaveops.demo` подтвердил: заявка аналитика Б на 14–16 октября блокируется из-за покрытия 14 октября; период 15–16 октября согласуется, сохраняется после повторного открытия базы и затем отменяется. История: draft → submitted → approved → cancelled.

`python -m leaveops.integration_demo` воспроизвёл потерю ответа после внешней записи. Событие осталось `pending` после первой попытки, повтор получил тот же `external_id`, а Mock Bitrix24 сохранил один календарный объект. Отмена доставлена отдельной командой.

Десять HTTP-тестов запускают реальный локальный сервер на временном порту. В браузере проверены HR-сводная, календарь доступности, причины блокировки, предложение переноса и повторное решение руководителя. Ручная кнопка синхронизации видна только руководителю демо.

## Живые smoke-тесты Bitrix24

Живые проверки выполнялись вручную на тестовом облачном портале и не входят в CI.

Webhook подтвердил Calendar scope и наличие шести требуемых методов, включая `calendar.event.update`. Smoke-сценарий создал синтетическое событие на весь день за 15–16 января 2099 года, нашёл его через `calendar.event.get`, удалил через `calendar.event.delete` и подтвердил отсутствие повторным чтением.

После выбора модели личных разделов созданы три раздела `LeaveOps — отсутствия` у разных владельцев. Проверены:

- создание, чтение и удаление события у двух разных владельцев;
- маршрутизация синтетического разработчика в личный календарь другого пользователя;
- создание и отмена с одним `external_id`;
- изменение периода через `calendar.event.update` без создания второго объекта;
- отсутствие тестовых событий после завершения проверок.

Webhook URL, token и runtime mapping в репозиторий не добавлены.

## Ограничения доказательств

- Это функциональная проверка небольшого синтетического набора, а не нагрузочный тест или production UAT.
- Реальной аутентификации, production server, scheduler, monitoring и операционного SLA нет.
- Полная карта всех шести синтетических сотрудников и уведомления целевого пользователя Bitrix24 не проверены.
- Reconciliation с ручными изменениями Bitrix24 отсутствует; `RISK-006` остаётся открытым.
- Юридически значимые остатки, праздники, смены, компенсации и кадровые расчёты не реализованы.
- Коммерческий эффект не измерялся.
