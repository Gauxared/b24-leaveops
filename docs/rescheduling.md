# Перенос согласованного периода

Сотрудник может предложить новые даты для уже согласованного отсутствия. Изменение требует отдельного решения руководителя.

## Процесс

1. Старый период остаётся действующим после создания предложения.
2. Руководитель видит действующие и предложенные даты, результат проверки покрытия и прогноз баланса.
3. При согласовании сервис повторно проверяет новые даты, меняет период заявки, сохраняет историю и ставит техническое событие обновления.
4. При отклонении исходный период не меняется; сотрудник видит причину и может предложить другой вариант.

## Доставка в Bitrix24

- Если календарное событие уже создано, адаптер вызывает `calendar.event.update` с известным `external_id`, прежними `owner_id` и `section_id`.
- Повтор обновляет существующее событие и не создаёт второе.
- Если создание ещё ожидает доставки, система меняет его payload вместо постановки обновления без внешнего ID.
- Ошибка внешней доставки оставляет событие в технической очереди и не отменяет решение руководителя.

Не поддерживаются массовые переносы, смена владельца календаря, обратная синхронизация и уведомления участников.
