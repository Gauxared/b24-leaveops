# Обобщённый процесс AS-IS

> AS-IS используется для постановки задачи и не описывает утверждённый регламент конкретной организации.

![BPMN 2.0 AS-IS](../diagrams/rendered/as-is.svg)

[Исходник BPMN 2.0 XML](../diagrams/src/as-is.bpmn)

## Участники

- pool «Организация» с lanes «Сотрудник», «Руководитель», «HR»;
- внешний pool «Bitrix24 Calendar».

Bitrix24 моделируется отдельным participant. Сведения передаются message flow; sequence flow не пересекает границу pool.

## Основной поток

1. Сотрудник сообщает даты отсутствия.
2. Руководитель вручную сверяет календарь команды.
3. HR отдельно проверяет остаток.
4. Руководитель согласует либо отклоняет период.
5. При согласовании HR обновляет регистр и отдельно передаёт даты для календаря.
6. Событие вручную вносится в Bitrix24.

## Наблюдения

Ручная передача разделяет контекст решения, основание согласования, рабочий регистр и календарную запись. Изменение уже согласованного периода и восстановление истории требуют сверки нескольких источников. Наблюдения формализованы как [`PP-001`–`PP-006`](../discovery/pain-points.md); технические угрозы автоматизированной доставки описаны отдельно как [интеграционные риски](../architecture/integration-risks.md).
